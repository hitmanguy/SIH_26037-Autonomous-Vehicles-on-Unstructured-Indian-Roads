
# Vehicle Dynamics and Control Plan

## Objective

Convert the path generated by the planning layer into safe, smooth and physically feasible steering, throttle and brake commands. The controller must track paths through unstructured Indian-road scenarios while limiting lateral error, longitudinal error, jerk and sudden actuator changes during replanning.

## POC Scope

The first proof of concept will use a kinematic bicycle model and a reference path with speed targets. It will compare:

- Standard Pure Pursuit as a baseline.
- Adaptive Pure Pursuit (A-PP), with lookahead adjusted using vehicle speed, path curvature and lateral error.
- A basic MPC controller for higher-speed path tracking.
- A speed-based handover with a short blend window so the switch between A-PP and MPC does not create a steering or acceleration spike.

The POC should report lateral tracking error, heading error, steering command, acceleration, braking demand, peak jerk and path completion. It should include at least a tight-turn case and a sudden-replan or emergency-stop case.

## Future MATLAB and Simulink Implementations

### 1. Vehicle model

- Implement the kinematic bicycle model in MATLAB and Simulink for initial controller development.
- Replace or cross-check it with a Vehicle Dynamics Blockset model for tyre forces, slip, load transfer and actuator limits.
- Add configurable vehicle parameters such as wheelbase, mass, steering limits, acceleration limits and braking response.
- Validate the model at low speed, highway speed and during emergency braking.

### 2. Adaptive Pure Pursuit

- Implement A-PP as a MATLAB Function block or Simulink subsystem.
- Increase lookahead with speed for stability and reduce it when curvature or lateral error increases for tighter tracking.
- Clamp lookahead and steering to physically valid limits.
- Add curvature-aware target-speed reduction before sharp turns and obstacle avoidance manoeuvres.

### 3. MPC controller

- Implement a discrete bicycle-model MPC for high-speed tracking and highway merges.
- Optimise steering, throttle and brake while respecting steering-rate, acceleration, deceleration and lateral-acceleration constraints.
- Include path curvature, predicted obstacle occupancy and planner speed limits in the cost function.
- Compare computation time and tracking quality against A-PP before enabling MPC in the closed loop.

### 4. Controller selection and smooth handover

- Select A-PP or MPC from measured vehicle speed, rather than from a hard-coded scenario name.
- Use hysteresis around the speed threshold to prevent rapid controller toggling.
- Blend steering and longitudinal commands over a short configurable interval during handover.
- Use a shorter blend for an emergency stop and a longer blend after an ordinary reroute.

### 5. Replanning and safety response

- Consume the planner's smoothed path, speed profile and urgency/blend information.
- Recompute the control target whenever a new path arrives, while rate-limiting sudden command changes.
- Add explicit STOP, YIELD and REROUTE responses for cattle, pedestrians, potholes and blocked paths.
- Prioritise braking and vehicle stability when the predicted path becomes unsafe; do not allow path tracking to override a safety stop.

### 6. Closed-loop Simulink integration

- Connect perception/fusion/prediction outputs to the dynamic occupancy costmap and planner interfaces.
- Connect the planner's path and speed profile to the controller, then feed vehicle pose and velocity back into the loop.
- Log timestamps at perception, prediction, planning and control so end-to-end replanning latency can be measured.
- Run the integrated model in RoadRunner scenarios: unmarked village road, unsignalled urban intersection, highway merge, dense market and sudden cattle crossing.

## Expected Future Implementation

The target implementation is a reusable MATLAB/Simulink subsystem with the following interface:

**Inputs:** vehicle pose and velocity, planned path, target speed, path curvature, predicted obstacle occupancy, planner mode and emergency flag.

**Outputs:** steering angle, steering rate request, throttle request, brake request and controller-status diagnostics.

The expected runtime behaviour is:

1. Use A-PP for low-speed, cluttered and high-curvature driving.
2. Use MPC for higher-speed tracking and highway merges when the compute budget permits.
3. Blend controller outputs during handover and after normal replans.
4. Override tracking with a bounded emergency braking response when a hard safety condition is detected.
5. Return vehicle-state feedback to the planner and log all control and safety metrics.

## Validation and Acceptance Criteria

- Compare A-PP, MPC and the adaptive controller on the same reference paths and initial conditions.
- Measure mean, 95th-percentile and maximum lateral error, heading error, steering rate, acceleration, jerk and controller execution time.
- Verify that the vehicle completes each target scenario without collision or unrecoverable tracking loss.
- Verify that controller handover does not produce a discontinuity beyond configured steering and acceleration limits.
- Verify that emergency braking remains stable and that the vehicle can resume or reroute after the hazard clears.

## Planned Deliverables

1. MATLAB script for bicycle-model simulation and controller comparison.
2. Simulink controller subsystem with tunable parameters and logged signals.
3. Vehicle Dynamics Blockset validation model, if the required toolbox is available.
4. RoadRunner scenario tests and a metrics table for all five scenarios.
5. Final closed-loop demo showing adaptive control during normal driving, replanning and emergency response.
